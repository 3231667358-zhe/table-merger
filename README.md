# table-merger —— Excel / CSV 批量合并与字段标准化工具 V1

把一个文件夹里所有表格（`.csv` / `.txt` / `.xlsx`）合并成一张 CSV。
各文件列名写法不一样没关系：工具会按列名对齐，缺的格子留空，**永远不会覆盖你的原始文件**。

## 两条硬规则（先看这个）

**规则一：字段别名只认显式配置，工具不猜语义。**
「名字」和「姓名」是不是同一个字段，由你写在别名表里说了算。
不写，它们就是两个不同的列。
项目自带的 `aliases.txt` 是一份**一条都没启用的空模板**，所以默认状态下工具不做任何字段归并。

**规则二：同一张表里两列归到同一个列名 → 直接报错停机。**
一个文件里同时有「姓名」和「名字」两列，而你配了 `姓名 = 名字`，那同一行的两个值就要抢同一个输出格子，
必然丢数据。这种情况下工具**不会自动改名、不会静默合并、也不会丢掉其中一列**，
而是打印出是哪两列撞了、怎么修，然后整个任务中止，**不产出任何文件**。

（跨文件归到同一列不算撞车：那是不同行、不同格子，不覆盖也不丢数据 —— 这正是别名表的用途。）

其它几件值得注意的事：

- **缺的列留空**：销售部没有「部门」列，那几格就是空的
- **全角转半角**：`１００３` → `1003`，`１００７` → `1007`
- **去首尾空白**：` 新入职 ` → `新入职`
- **没有去重**：李四和孙七在不同文件里出现，两行都保留（V1 不去重）

## 三条规则

### 1. 列名标准化

先做通用标准化，再查别名表：

| 处理 | 例子 |
|---|---|
| 去首尾空白 | `" 姓名 "` → `姓名` |
| 全角字母数字转半角 | `"ＮＡＭＥ"` → `NAME`、`"１００１"` → `1001` |
| 比对时忽略大小写 | `Name` / `NAME` / `name` 视为同一列 |
| 别名归并 | `名字` → `姓名`（**只有你配置了才生效**） |

**显示用的列名保留第一次出现的写法**，只是内部比对时忽略大小写。
所以第一个文件写 `Name`，结果表头就显示 `Name`，不会强制变成小写。

> 注意：全角**标点**不转。`北京，上海` 里的逗号是中文正文的一部分，转了就等于改数据。
> 只转全角字母、数字和全角空格。

#### 别名表怎么配

默认加载 `merge.py` 旁边的 `aliases.txt`（空模板，全注释）。格式：

```
标准名 = 别名1, 别名2, 别名3
```

- 等号左边 = 输出表里显示的名字；右边 = 各源文件里可能出现的写法
- 分隔符可用英文逗号、中文逗号、顿号，随便混用；`#` 开头是注释
- 标准名自己也算自己的别名，不用重复写
- 同一别名被指到两个标准名 → 直接报错（工具不替你猜）

换文件：`--aliases 我的别名表.txt`；完全不用：`--no-aliases`。

### 2. 值标准化

每个单元格：去首尾空白 + 全角字母数字转半角。
**空单元格不会被填成 0 或 NULL**，整行都是空白的行会被跳过（Excel 表尾常有一堆这种空行）。

### 3. 永不覆盖

- **永远不覆盖任何输入文件（硬闸门）**：`-o` 和 `--report` 要写入的路径，
  都不允许指向输入目录里**现有的表格文件**。按 `resolve()` 后的真实路径判断，
  所以符号链接绕不过去；**加 `--force` 也不行** —— `--force` 只放宽「覆盖你自己以前的输出」，
  永远不放宽「覆盖原始数据」。
- 输出文件已存在时，必须显式加 `--force` 才会覆盖
- 所有检查（读文件、查公式、查列名撞车、查写入目标）都在**任何 mkdir / 写文件之前**完成，
  **被拒绝时磁盘上不会多出任何文件**，连父目录都不会被创建
- 输入目录里 `*_merged.csv` 结尾的文件扫目录时会跳过（那是上一次的产物）；
  但它仍然算「目录里既有的文件」，**不能被当成写入目标** —— 否则「跳过」就成了覆盖它的通道

> 为什么不做「把输出/报告从扫描里排除掉」：那等于用排除法掩盖冲突。
> 如果要写的文件恰好就是源表，它一被排除，后面的安全检查就再也看不见它了，
> 结果就是源表被覆盖。所以扫描**不做任何排除**，写入目标的安全性由单独的硬闸门把关。
>
> 由此带来的一条使用建议：**别把 `-o` / `--report` 写在输入目录里面**。
> 写进去（比如 `--report data/报告.txt`）第一次能成功，因为那时文件还不存在；
> 第二次运行它会变成「目录里现有的表格文件」，于是被硬闸门拒绝。
> 默认输出本来就在输入目录的旁边，按默认走不会有这个问题。

## 参数

| 参数 | 作用 |
|---|---|
| `directory` | 要合并的目录（只扫这一层，不递归子目录） |
| `-o`, `--output` | 结果写到哪；默认在输入目录旁边生成「目录名_merged.csv」 |
| `--report 文件` | 把统计结果额外写一份文本文件 |
| `--aliases 文件` | 用指定的别名表；默认自动找脚本旁边的 `aliases.txt` |
| `--no-aliases` | 完全不用别名表 |
| `--no-source-col` | 不要在结果最左边加「来源文件」列 |
| `--force` | 输出文件已存在时允许覆盖（**绝不包括输入表**） |

```bash
python3 merge.py -h
```

## 什么情况下会被拒绝

| 情况 | 处理 |
|---|---|
| `-o` 或 `--report` 指向输入目录里现有的表格文件 | **报错停机，`--force` 也不能放行**，一个字都不改写 |
| 写入目标是符号链接、但最终指向输入表 | 报错停机（按 `resolve()` 后的真实路径判） |
| 同一张表里两列归到同一个列名 | 报错停机，指出哪两列撞了，不产出文件 |
| 输入自带「来源文件」列（会和工具的来源列重名） | 报错停机；加 `--no-source-col` 或改源文件列名即可 |
| `.xlsx` 里有真正的公式，或有 `=` 开头的文本 | 报错停机，不产出文件 |
| `.xlsx` 打不开／损坏 | 报错停机，不产出文件 |
| 输出文件已存在（且不是输入表） | 报错停机；加 `--force` 才会覆盖 |
| `--report` 和 `-o` 是同一个路径 | 报错停机 |
| 目录里没有表格 | 报错停机 |
| `.xlsm` / `.xls` / `.xlsb` | 跳过该文件 + 警告，其余照常合并 |
| 其它非表格文件（`.md`、`.bak`…） | 忽略，并在摘要里说明有几个 |

不支持的格式之所以是「跳过 + 警告」而不是停机，是因为批量场景里一个无关文件不该毁掉整批；
而「打不开」「含公式」「列名撞车」「写入目标撞源表」会让数据不可信或直接毁数据，
宁可整批停下也不给你一份看着成功、实际缺数据的结果。

## 已知限制（V1 故意的）

- **不支持 `.xlsm`**：本工具要重建表，宏（VBA）没办法安全保留，硬做会静默丢宏。目录里见到会跳过并警告。请先在 Excel 里另存为 `.xlsx`。
- **不支持 `.xls` / `.xlsb`**：V1 不解析这两种老格式，同样跳过并警告。
- **`.xlsx` 必须是无公式的纯数据表**（原因见上表）。
- **不做格式转换**：只输出 CSV（UTF-8 带 BOM，Windows 版 Excel 双击不乱码）。`-o` 只能是 `.csv`。
- **不做去重、不做类型判断**：日期和数字不会被「识别」成特殊类型，只做文本级的清洗。
- **只扫一层**：子目录不递归。
- **全量读进内存**：文件很大（几百万行）会很吃内存，V1 不做流式。
- **`.xlsx` 每张工作表各算一张表**：只有一张表时来源标记就是文件名；多张表时是 `文件名#表名`。
- Excel 只搬单元格的值：颜色、字体、列宽、合并单元格都不保留。
